# Marve Invest

PHP 8.2 / MySQL 8 foundation for a Nigerian equity-investment platform. It deliberately does **not** contain seeded prices, demo balances, fake trades, or simulated returns.

## Local setup

1. Copy `.env.example` to `.env`, then set database credentials and secure keys. Never commit `.env`.
2. Import `database/mysql/schema.sql` with MySQL 8+.
3. Serve the project over HTTPS with PHP 8.2+, ensuring `storage/` and `.env` are outside the public document root in production.
4. Use `index.php` as the entry point; APIs are under `/api/v1/index.php`.

## Provider configuration

Market data is intentionally `UNAVAILABLE` until NGN Market is configured server-side. Set `MARKET_DATA_PROVIDER=ngnmarket`, `MARKET_DATA_API_URL=https://api.ngnmarket.com`, a valid `MARKET_DATA_API_KEY`, and the entitlement supplied by the provider (`LIVE`, `DELAYED`, or `END_OF_DAY`). The credential is read only from environment configuration and is never sent to the browser. The provider validates company-list responses and caches only returned quotes in `market_quotes`; it never seeds or fabricates prices.

Paystack is server-side only. `app/Payments/PaystackService.php` initializes payments; a webhook route must validate HMAC SHA-512, verify the provider transaction and then use `LedgerService::creditDeposit()` in the same controlled flow. Never credit from a browser callback.

## Current scope

Included: secure session defaults, CSRF guard, database access via PDO prepared statements, registration/login foundation, rate limits, provider abstractions, fixed-decimal wallet and immutable ledger schema, payment idempotency tables, orders with accurate provider-state model, audit logging, and a responsive application shell.

Still required before production: TOTP implementation, a licensed NGX provider adapter + WebSocket process, Paystack webhook/verification endpoint, approved broker integration, full RBAC middleware, admin application, reconciler/cron jobs, independent security audit, and test suite.


Marve Invest is a PHP 8.2 and MySQL 8 foundation for a Nigerian-equities investment website: the visitor-facing dashboard in `index.php` provides the responsive Marve interface, account-access dialog, platform-status notices, market-overview area, and empty-state messaging, while `public/assets/css/app.css` supplies its visual layout, typography, colors, responsive behavior, and component styling and `public/assets/js/app.js` supplies the browser-side behavior that retrieves a CSRF token and market status, opens and submits the sign-in or registration dialog, and displays API feedback; `app/bootstrap.php` is loaded by both the page and API and sets up autoloading, secure session handling, and browser security headers, `app/Config/Env.php` reads server-only configuration from `.env`, `app/Core/Database.php` creates the PDO connection used by the backend, and `app/Core/Api.php` formats consistent JSON success and error responses. The API gateway is `api/v1/index.php`: it receives the frontend's requests, routes CSRF, market-overview, registration, login, current-user, and Paystack webhook calls, applies rate limits and CSRF checks, and delegates work to the focused service files. `app/Security/RequestSecurity.php` manages session safety, request validation, rate limiting, login checks, and CSRF protection; `app/Auth/AuthService.php` validates registration and login data, hashes passwords, and manages user authentication; `app/Market/MarketDataProviderInterface.php` defines the contract any authorised NGX market-data provider must satisfy, `app/Market/UnavailableMarketDataProvider.php` deliberately returns an unavailable state until such a provider is connected, and `app/Market/MarketDataService.php` turns provider data into the overview consumed by the dashboard. Payments are intentionally server controlled: `app/Payments/PaystackService.php` initializes and verifies Paystack transactions and validates webhook signatures, while `app/Wallet/LedgerService.php` records verified deposits as fixed-decimal, append-only ledger entries instead of allowing a browser callback to change a balance. The persistence layer lives in `database/mysql/schema.sql`, which creates the MySQL tables for roles and permissions, users and verification/security records, assets and market history, watchlists, wallets and immutable ledger entries, payment/webhook idempotency, orders, and audit logs; `database/mysql/seed_dev.sql` explicitly contains no fake financial data, `database/mysql/README.md` explains safe database import and financial-data constraints, and `database/mysql/ERD.md` diagrams the principal database relationships. `storage/logs/.gitkeep` keeps the otherwise empty log directory under version control. To run the website locally, copy `.env.example` to `.env` and set the database credentials and secure keys, import `database/mysql/schema.sql` into MySQL 8+, serve this folder with PHP 8.2 or later, and open `index.php`; keep `.env` and `storage/` outside the public document root in production. The interface remains intentionally honest until real integrations are approved and configured: it has no seeded prices, demo balances, fabricated orders, or simulated returns, and production deployment still needs authorised NGX data and broker integrations, transaction-email delivery and verification, TOTP, complete RBAC and administration, scheduled reconciliation, and an independent security audit.
